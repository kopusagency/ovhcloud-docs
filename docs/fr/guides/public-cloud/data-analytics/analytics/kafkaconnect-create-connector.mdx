## Objectif

Kafka Connect déplace des données entre vos topics Kafka et des systèmes externes grâce à des connecteurs prêts à l'emploi : les connecteurs source font entrer des données dans Kafka, les connecteurs sink copient les données de Kafka vers un autre système.

Ce guide explique comment relier un service Kafka Connect à votre service Kafka, puis comment créer, suivre et gérer un connecteur avec l'API OVHcloud. L'exemple copie les messages d'un topic Kafka dans une collection Public Cloud Databases for MongoDB.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Un [service Kafka](/guides/public-cloud/data-analytics/analytics/kafka-create-cluster) avec un topic, ici `orders`, dont les messages sont des documents JSON
- Un service Kafka Connect dans le même projet Public Cloud
- Pour l'exemple : un service Public Cloud Databases for MongoDB, et un utilisateur MongoDB disposant du rôle `readWrite` sur la base cible
- Un accès à l'[API OVHcloud](/guides/manage-and-operate/api/first-steps)

## En pratique

### Étape 1 - Relier Kafka Connect à votre service Kafka

Kafka Connect lit et écrit dans un service Kafka du même projet grâce à une intégration. Créez-la sur votre service Kafka Connect :

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/integration"} />

```json
{
  "type": "kafkaConnect",
  "sourceServiceId": "<ID du service Kafka>",
  "destinationServiceId": "<ID du service Kafka Connect>"
}
```

L'intégration est prête immédiatement :

```json
{
  "id": "<ID de l'intégration>",
  "sourceServiceId": "<ID du service Kafka>",
  "destinationServiceId": "<ID du service Kafka Connect>",
  "type": "kafkaConnect",
  "status": "READY"
}
```

### Étape 2 - Autoriser Kafka Connect à joindre le système cible

Un connecteur se connecte au système externe depuis votre nœud Kafka Connect. Pour un service Kafka Connect public, trouvez l'adresse IP du nœud en résolvant son nom d'hôte, affiché dans les `nodes` du détail du service :

```bash
dig +short kafkaconnect-xxxxxxxx-xxxxxxxxx-1.database.cloud.ovh.net
```

Ajoutez ensuite cette adresse IP aux IP autorisées du service cible, ici le service MongoDB.

### Étape 3 - Choisir un connecteur

Listez les connecteurs disponibles sur votre service Kafka Connect, puis consultez le détail de chacun :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/capabilities/connector"} />

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/capabilities/connector/\{connectorId\}"} />

```json
{
  "id": "<ID du connecteur>",
  "name": "MongoDB Kafka Sink Connector",
  "author": "MongoDB",
  "documentationUrl": "https://docs.mongodb.com/kafka-connector/current/",
  "preview": false,
  "type": "sink",
  "version": "1.16.0",
  "latest": true
}
```

Conservez l'`id` du connecteur à utiliser. Le champ `documentationUrl` renvoie vers la documentation du connecteur, qui liste ses propriétés de configuration. Vous pouvez aussi parcourir la [liste des connecteurs disponibles](/guides/public-cloud/databases/kafkaconnect-available-connectors).

### Étape 4 - Créer le connecteur

Créez le connecteur avec l'`id` de sa capacité, un nom et sa configuration :

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/connector"} />

```json
{
  "name": "orders-to-mongodb",
  "connectorId": "<ID du connecteur>",
  "configuration": {
    "connector.class": "com.mongodb.kafka.connect.MongoSinkConnector",
    "topics": "orders",
    "connection.uri": "mongodb+srv://<username>:<password>@<hôte MongoDB>/admin?replicaSet=replicaset&tls=true",
    "database": "shop",
    "collection": "orders",
    "key.converter": "org.apache.kafka.connect.storage.StringConverter",
    "value.converter": "org.apache.kafka.connect.json.JsonConverter",
    "value.converter.schemas.enable": "false"
  }
}
```

Dans cette configuration :

- `topics` est le topic Kafka à lire ;
- `connection.uri`, `database` et `collection` définissent où les messages sont écrits dans MongoDB ;
- les convertisseurs lisent les clés des messages comme des chaînes de caractères et leurs valeurs comme des documents JSON sans schéma.

Kafka Connect vérifie la configuration à la création du connecteur. Si le système cible est injoignable, par exemple parce que l'adresse IP de Kafka Connect n'est pas encore autorisée, l'API renvoie une erreur `400` avec le message `Unable to connect to the server.`

:::warning
La configuration d'un connecteur, y compris les mots de passe qu'elle contient, est renvoyée en clair par l'API. Utilisez un utilisateur dédié, avec uniquement les permissions nécessaires au connecteur.
:::

Chaque message du topic `orders` est désormais écrit comme un document de la collection `shop.orders`. Par exemple, le message `{"amount":42}` devient le document `{ "_id": ObjectId("..."), "amount": 42 }`.

### Étape 5 - Suivre le connecteur

Consultez l'état du connecteur, puis listez ses tâches et l'état de chacune :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/connector/\{connectorId\}"} />

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/connector/\{connectorId\}/task"} />

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/connector/\{connectorId\}/task/\{taskId\}"} />

```json
{"id":0,"trace":"","status":"RUNNING"}
```

Les tâches effectuent le travail du connecteur : un connecteur fonctionne lorsque ses tâches sont `RUNNING`.

### Étape 6 - Mettre en pause, reprendre, redémarrer ou supprimer le connecteur

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/connector/\{connectorId\}/pause"} />

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/connector/\{connectorId\}/resume"} />

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/connector/\{connectorId\}/restart"} />

<Api version="v1" section="/cloud" method="DELETE" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/connector/\{connectorId\}"} />

:::info
Après une pause, vérifiez l'état des tâches : elles passent à `PAUSED`, alors que l'état du connecteur lui-même peut rester `RUNNING`.
:::
